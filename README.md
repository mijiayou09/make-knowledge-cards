# make-knowledge-cards

一个 Codex Skill：把用户粘贴的文章，或本地 Markdown / TXT 文件，转换成 5–8 张可复习的知识卡片。

每张卡片固定包含四部分：**标题、核心知识、简明解释、例子或自测问题**。

## 1. 解决什么问题

读完一篇长文，过几天往往只剩模糊印象；手动做笔记又容易走向两个极端——要么抄全文，要么只记几句干标题，中间缺了“一个知识点一张卡”的粒度。

直接让模型去总结，还会撞上三个典型毛病：

- 挑走漂亮句子，而不是真正承重的知识；
- 同一件事被拆成好几张卡，或者换个说法又出现一次；
- 为了把数量凑够，编造原文里没有的数据、原因和例子。

这个技能把这三件事写成明确规则：有选点标准、有去重规则、有禁止编造的红线，并且要求信息不足时如实说明，而不是把卡片硬凑到 5 张。

## 2. 主要功能

**支持的输入**

- 直接粘贴在对话里的文章正文。
- 本地 `.md` / `.txt` 文件路径；优先按 UTF-8 读取，出现乱码时用 GB18030 重试一次。
- 一次处理一个来源；给了多个文件时，先确认是合并成一套卡片还是逐个处理。

**输出**

- 默认 5–8 张卡片，语言与原文一致（中文原文出中文卡片，英文原文出英文卡片），以 Markdown 直接回复。
- 每张卡四个字段：标题 / 核心知识 / 简明解释 / 例子或自测。英文原文时字段名换成 Title / Core idea / Explanation / Example or self-test question。
- 结尾用一行交代来源（文件名或“粘贴文本”）、卡片数和必要说明。
- 只有用户明确要求时才写入文件。

**选点与粒度**

- 优先保留“读者不知道就会吃亏”的内容：中心论点、关键概念、因果机制、判断标准与可操作步骤、本身就是信息量的数字、原文专门澄清的误解。
- 背景铺垫、过渡句、作者感慨、与主题无关的细节、换个说法重复的观点，不单独成卡。
- 一张卡片只讲一个知识点：一个候选点里含两个独立想法就拆开，同一观点换说法只留一张，同一原则的正反面合并成一张。
- 标题一律写成判断句，不写话题名。术语型文章也一样：卡片标题写“确认偏误让人只寻找支持自己的证据”，术语名放在解释里。

**不编造**

- 卡片里的每一项都必须在原文中有依据，不补充原文没有的事实、数字、人名、日期、原因和例子。
- 不用背景知识补全机制：原文只说“睡满一个完整周期才包含慢波睡眠”，就不再添加“慢波睡眠出现在周期后段”。
- 原文没有例子时，把“例子 / 自测”字段改写成自测问题；自测问题可以重新措辞，但答案必须能在原文中找到。
- 原文含糊或前后矛盾时如实标注，不替它补全。

**回复前自检**

交付前会过一遍五条检查：每张卡只讲一个点且互不重复、每条内容都能在原文找到出处、抽掉任何一张都会损失一件承重信息、数量是 5–8 张或差异有明确理由、输出语言与原文一致。

**数量规则**

- 目标 5–8 张；原文能支撑 8 个以上要点时，取最承重的 8 张，并说明略去了哪些主题。
- 清单、术语表这类各点价值相当的文章，不凭主观挑“最重要的”，而是按原文顺序保留前 8 条，并列出被略去的条目名。
- 有解释、机制或可操作信息的独立要点不足 5 个时，按实际数量交付，并说明“原文只支持 N 个知识点”。
- 原文只有孤立事实（一条条通知、数据，没有解释也没有可迁移的判断）时不出卡片，而是说明素材不足，并列出补充哪类内容（原因、机制、影响）后可以出卡。

**暂不支持**

- 网页抓取 / URL（请把正文粘贴进来）、PDF（请先转成文本或 Markdown）、Anki 与任何牌组格式导出、图形界面或应用输出。

技能不含任何脚本，全部逻辑都在 `SKILL.md` 里。

## 3. 安装方法

技能目录需要放进 Codex 的技能发现路径（`$CODEX_HOME/skills`，未设置 `CODEX_HOME` 时是 `~/.codex/skills`）。在仓库根目录执行：

```powershell
$skillsDir = if ($env:CODEX_HOME) { Join-Path $env:CODEX_HOME 'skills' } else { Join-Path $env:USERPROFILE '.codex\skills' }
New-Item -ItemType Directory -Force -Path $skillsDir | Out-Null
Copy-Item -Recurse -Force .\skills\make-knowledge-cards $skillsDir
```

- 目录名要保持 `make-knowledge-cards`：它必须与 `SKILL.md` 里的 `name` 一致，改名会导致技能无法被识别。
- 没有第三方依赖，不需要安装任何库。
- 卸载就是删掉 `$skillsDir\make-knowledge-cards` 这个目录。

## 4. 使用方法

显式调用，正文直接粘贴：

```text
$make-knowledge-cards 把这篇文章做成知识卡片：
<粘贴正文>
```

也可以直接给文件路径，用自然语言说就行：

```text
把 D:\notes\sleep.md 转成知识卡片
```

用户提出“要知识卡片”或“从这篇文章里提取核心知识”这类需求时，技能会被自动选用；下面是几个常见的追加要求：

```text
把结果保存成 cards.md
把被略去的那两条也补上
```

## 5. 输入输出示例

### 示例 A：粘贴一段文章

输入：

```text
睡眠不是大脑的“关机”，而是记忆整理的第二道工序。白天学到的东西先以临时形式存放在海马体，
容量有限、容易覆盖；夜里慢波睡眠期间，海马体把白天的经历重新“播放”给皮层，皮层据此建立更
稳定的连接，这就是记忆巩固。

值得注意的是，睡眠不足首先伤害的不是“回忆”，而是“编码”——也就是形成新记忆的能力。连续熬夜
的人常常发现自己记不住新东西，就是因为海马体没有腾出空间。

时机也很关键。学习之后当晚的睡眠，对巩固的效果远高于几天后再补觉，补睡无法把已经流失的巩固
过程追回来。另外，午睡 20 分钟只停留在浅睡阶段，几乎不参与巩固；睡满 90 分钟完成一个完整
周期，才会包含慢波睡眠。

最后是咖啡因。咖啡因的半衰期约为 5 小时，下午三点喝的一杯咖啡，到半夜仍有一半留在体内，它会
压缩慢波睡眠的时长。如果你发现睡够 8 小时仍然疲惫，可以先检查睡前的咖啡因。
```

输出：

### 卡片 1：睡眠负责把白天的经历搬进长期记忆
**核心知识**：慢波睡眠期间，海马体把白天的经历重放给皮层，皮层据此建立更稳定的连接，完成记忆巩固。
**简明解释**：白天学到的东西先以临时形式存放在海马体，容量有限、容易被覆盖。睡眠不是关机，而是把这些内容搬迁到皮层。
**例子 / 自测**：为什么白天学的内容需要“过夜”才能变成长期记忆？

### 卡片 2：睡眠不足首先伤害的是“编码”，不是“回忆”
**核心知识**：缺觉首先损害的是形成新记忆的能力，而不是调取旧记忆的能力。
**简明解释**：海马体没能腾出空间，新信息就放不进去。所以熬夜的人常常是记不住新东西，而不是想不起旧东西。
**例子 / 自测**：连续熬夜的人“记不住新东西”，对应记忆的哪个环节？

### 卡片 3：学习后当晚的睡眠，比事后补觉更重要
**核心知识**：学习之后当晚的睡眠对巩固的效果，远高于几天后再补觉。
**简明解释**：补睡无法把已经流失的巩固过程追回来，所以同一段睡眠发生在什么时候，效果并不相同。
**例子 / 自测**：为什么熬夜备考不如睡够再早起复习？

### 卡片 4：午睡时长决定它是否参与记忆巩固
**核心知识**：20 分钟午睡只停留在浅睡阶段，几乎不参与巩固；睡满 90 分钟完成一个完整周期，才包含慢波睡眠。
**简明解释**：巩固发生在慢波睡眠里，而浅睡拿不到这段收益。想靠午睡帮助记忆，时长是关键。
**例子 / 自测**：想靠午睡帮助记忆，该睡 20 分钟还是 90 分钟？

### 卡片 5：下午的咖啡因会压缩慢波睡眠
**核心知识**：咖啡因半衰期约 5 小时，下午喝的咖啡到半夜仍有一半留在体内，会压缩慢波睡眠时长。
**简明解释**：睡够 8 小时仍然疲惫，不一定要延长睡眠时间，可以先检查睡前的咖啡因。
**例子 / 自测**：一个人每天睡够 8 小时仍然疲惫，可以先排查什么？

来源：粘贴文本，共 5 张卡片。

### 示例 B：信息不足的简讯（不出卡片）

输入：

```text
本市地铁 3 号线将于本月 20 日恢复全线运营，此前因信号系统升级停运两周。运营方表示早高峰发车
间隔将由此前的 3 分钟缩短至 2 分 30 秒。
```

输出：

```text
素材不足，暂不出卡片。

这篇简讯只有两个事实（3 号线本月 20 日恢复运营、早高峰间隔由 3 分钟缩短到 2 分 30 秒），没有
解释、机制或可迁移的判断，做成知识卡片只会退化成“记住两条通知”。

如果需要卡片，可以补充以下任一内容后再发给我：

- 停运升级的原因与信号系统改动的具体情况；
- 2 分 30 秒的发车间隔在运力上意味着什么；
- 对乘客的实际影响，例如拥挤度或换乘建议。
```

### 示例 C：英文原文（字段名随原文切换）

输入：

```text
Freshness and validation are different things. Cache-Control: max-age=600 says the response is
fresh for ten minutes and can be reused without contacting the server. An ETag enables validation
instead: once the response is stale, the client sends If-None-Match, and the server replies 304
Not Modified with no body if nothing changed. Freshness avoids round trips; validation avoids
transferring bytes.
```

输出：

### 卡片 1：Freshness and validation solve different problems
**Core idea**：`max-age` avoids round trips; `ETag` + `304` avoids transferring bytes.
**Explanation**：A fresh response may be reused without contacting the server. Once it is stale, the client can validate with `If-None-Match` and get a bodyless `304` if nothing changed.
**Example or self-test question**：Which mechanism saves bandwidth but still needs a request?

Source: pasted text — 1 card (the text supports only one knowledge point).
